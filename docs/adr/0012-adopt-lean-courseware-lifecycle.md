# ADR 0012：以轻量责任链统一研发实验与生产编排

- 状态：已采纳
- 日期：2026-08-20
- 演进：ADR 0007、0008、0010、0011

## 背景

ADR 0011 决定用下一道真实题验证：不走旧 harness、九阶段状态和固定 A 级评审时，能否以较低治理成本做出有教学价值的课件并得到真实老师反馈。474 纵波实验完整走过真实题、物理与教学分析、Kimi 前端候选、Codex 独立检查、用户多轮体验、授权发布、稳定入口和顾问老师反馈。最终课件得到用户与顾问老师认可。

实验同时暴露：AI 起初把完整物理模型当成默认学习路径，造成过度讲解；老师确认学生真正困难是无法想象弹簧运动、不能把动态过程与静态点图连接后，课件才收敛为最低充分干预。本轮减少了旧治理步骤，但仍经历长上下文、多次方向纠偏和 36 次 Kimi 响应，因此只证明新路径可行一次，尚未证明低成本、稳定复制或学生学习效果。

`build-physics-courseware` 的职责是组织真实生产。若等待多题证明稳定后才让新路径进入该 skill，后续题目仍会被旧默认流程组织，无法产生新编排的生产证据。生产 skill 的迭代门槛与物理专家 skill 的跨题知识门槛不同：前者可以依据一次完整生命周期直接修正默认流程，后者仍不得把单题教学经验泛化为母模型或通用规则。

## 决策

1. **统一 skill 从研发实验开始。** 每道具名真实题从开始即使用 `$build-physics-courseware` 组织；研发实验与正式生产是同一证据链上的不同责任边界，不是两套流程。
2. **研发实验仍是默认起点。** 新题不自动进入 `production/`，不自动启用暂停的 harness、九阶段状态、生产状态单或 A0/A1/A2/A3。需要稳定老师试用链接也不等于正式转正。
3. **默认使用最短责任链。** 真实题 → 物理事实与学生障碍假设 → 必要的老师语言校准 → 最小临时任务书 → 前端候选 → Codex 独立检查 → 用户亲自体验 → 授权发布 → 老师自由反馈 → 最小结论。只有角色切换、产品选择、用户体验、外部写入授权、老师响应或真实证据缺口才停。
4. **认知障碍先作为假设。** AI 可以提出少量可观察的学生表现；当缺少课堂证据时，用题面词汇和普通语言请老师补充或纠正，不要求老师选择抽象标签或完成学生微任务。有老师或学生证据时，以直接证据校准。
5. **最低充分干预代替完整性默认。** 不要求每题采用完整母模型讲解、固定页面结构、固定维度或统一问题链。同一题的不同设问可以使用动画、比较、测量、图示或短推导等不同干预，只保留当前障碍和解题交接需要的内容。
6. **独立检查保留，等级仪式退出默认。** Codex 仍检查物理、教学目标、主要交互、资源、控制台和支持视口；用户体验仍是老师试用前的产品关口。只有物理脆弱、复杂空间交互、严重缺陷重复、系统性证据冲突、共享生产契约变化或面向不特定公众发布时，才升级独立物理复核或成品审查。
7. **正式化不重跑生命周期。** 用户明确批准转入正式生产后，创建轻量 `production/courseware/<courseware_id>/record.md` 和规范输入，承接实验中已成立的候选身份、证据、判断和未验证项；不为填字段重复物理、教学、实现或检查。
8. **滚动记录只保留恢复所需事实。** 新记录使用少量责任与恢复字段，不实现阶段状态机；正文持续合并直接证据、解释、决定、唯一下一动作、已验证/未验证、Token 观察和待复验经验。旧九阶段记录不批量改写，在收到新证据再次使用时就地迁移，并保留其历史放行事实。
9. **硬边界继续有效。** Kimi 只实现前端；物理结论和教学范围由 Codex 与产品判断负责；用户亲自体验；部署与外部写入需明确授权；revision 不可变；从老师真实入口核验；老师原话与产品解释分开；老师满意不冒充学生学会或跨题普遍有效。
10. **用真实生产继续验证。** 下一道未见真实题直接使用新版 skill，重点观察能否更早完成老师校准、减少方向返工和上下文依赖，并再次获得老师认可。失败时基于证据调整编排，不先恢复全部旧流程。

## 结果与限制

- `build-physics-courseware` 从只管理正式九阶段记录，改为管理一个具名课件从研发实验到老师反馈或正式生产的轻量生命周期。
- 旧物理复核、蓝图、独立成品检查和发布规则中的有效护栏成为条件分支，不再是每题必经阶段。
- 474 保持已完成研发实验身份，不因本 ADR 事后改写为正式生产。
- 本决定只改变生产编排默认值；不把 474 的动画形式、振幅讲法或学生障碍写入物理专家母模型、通用模板或质量标准。
- 当前不能宣称新流程已经稳定、成本更低或提升学生学习效果；这些是后续未见题和真实课堂需要继续验证的主张。

## 不采用

- **等待多题证明稳定后再修改生产 skill：** 后续题仍由旧流程组织，无法得到新流程的真实生产证据。
- **删除所有旧检查与历史记录：** 其中的物理、授权、不可变发布和风险升级经验仍有价值，也会破坏 q01/q07 的恢复。
- **只改 skill、不改仓库规则：** 会让运行协议与 `AGENTS.md`、`CONTEXT.md` 冲突，形成双重事实源。
- **同时泛化 physics-expert-agent-skill：** 单题足以修正编排默认值，不足以证明跨题物理或教学规律。
