# ADR 0013：用追加式处置记录结束旧老师评价任务

- 状态：已采纳
- 日期：2026-08-20
- 演进：ADR 0009、0011、0012

## 背景

ADR 0009 为 q01 v8 和 q07 建立了精确 revision 的六维评价任务。服务端只有“待评价”和“已评价”两种状态：没有结构化评价版本就持续显示“待评价”。ADR 0011 随后决定老师可以自由反馈，不再要求填写固定六维表单，但当时明确不批量修改 q01、q07 和评价服务。因此，老师长期题库仍把已经退出当前协议的旧任务显示为待办。

不能通过伪造六维评价把任务改成“已评价”，也不能删除或覆盖 ADR 0009 已经建立的不可变任务和历史。

## 决策

1. 评价任务增加第三种服务端状态 `closed`，界面显示“已结束”。它表示产品不再要求老师补填该任务，不等于老师完成评价、课件被接受或学生学会。
2. 结束任务使用 `feedback/reviews/<teacher_key>/<task_id>/` 下的不可变 `task_disposition` 对象。处置记录与评价版本共用现有只追加、可读的对象前缀，不删除或覆盖原任务，也不扩大运行角色权限。
3. 处置记录必须绑定精确 `task_id`、`courseware_id` 和 `revision_id`，包含决定时间、普通语言原因和正式决策引用。身份不一致或字段无效时服务端拒绝加载。
4. 已结束且没有评价历史的任务拒绝新的结构化提交。老师题库不再把它放入待评价列表；“我的评价”保留“已结束”区域供回看课件和理解历史状态。
5. q01 v8 与 q07 的旧固定表单任务按本决定结束，原因统一为固定六维表单已退出默认评价协议。此举只消除旧义务，不补写老师没有说过的话，也不解决既有反馈与精确 revision 归属不清的问题。
6. 新评价任务仍由产品负责人明确建立。结构化六维表单是可选意见入口，老师的自由反馈同样是有效证据。

## 结果与限制

- q01、q07 的旧任务在处置对象写入且新版评价服务与静态页面发布后，不再显示为“待评价”。
- 原任务、已有评价及老师长期链接保持不变；线上生效仍需单独授权 Git、部署和私有 OSS 追加写入。
- `closed` 不作为满意度、接受、题库晋升、学生效果或精确 revision 已体验的证据。

## 不采用

- **删除旧任务：** 破坏不可变历史，也超出运行角色权限。
- **补造一份六维评价：** 会把产品决定伪装成老师证据。
- **只在题库前端隐藏两个任务：** 服务端、评价页和生产记录仍会冲突，无法形成可恢复的单一事实。
