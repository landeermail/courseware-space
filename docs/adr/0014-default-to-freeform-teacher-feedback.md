# ADR 0014：老师试用默认使用自由反馈

- 状态：已采纳
- 日期：2026-08-20
- 演进：ADR 0009、0011、0013

## 背景

研发实验已经改为“老师试用后自由反馈”，但线上老师入口仍把服务端任务等同于固定六维评价：没有任务的课件无法显示等待反馈或已反馈，课件也没有新的自由反馈入口。474 纵波课件因此通过产品负责人转述获得了老师满意反馈，却没有进入线上反馈状态；首页同时保留了无任务的“待评价”空框。

治理规则已经改变而产品闭环没有改变，会让老师误以为仍需完成旧表单，也让真实自由反馈只能留在对话或实验记录中。

## 决策

1. 服务端任务继续绑定精确 `courseware_id` 和 `revision_id`，但它表示“当前希望听取老师意见”，不再默认表示必须填写六维表单。
2. 新任务默认使用 `feedback_mode: freeform`。老师只需提交一段自由文字；任务可以提供一条普通语言提示，但不得要求老师选择抽象维度。旧结构化任务继续可读、可修改，不批量伪装成自由反馈。
3. 老师首页把活动任务显示为“希望您重点体验 / 等待反馈”，没有活动任务时隐藏整个区域。“我的反馈”集中显示等待反馈、已反馈和已结束任务。
4. 自由反馈采用不可变追加版本，当前版本由最后一条记录决定。老师可补充反馈，旧版本只读，不覆盖历史。
5. 经产品负责人转述的老师反馈可以进入同一历史，但必须标记 `source_channel: product_owner_relay` 并保存稳定来源引用；界面显式显示转述来源，不冒充老师在线提交。
6. 474 建立精确自由反馈任务，并把已经记录在实验文件中的“老师也表示很满意”作为转述反馈追加保存，因此当前状态是“已反馈”，不是“等待反馈”。
7. 已发布的 474 不可变 revision 不为增加导航而原地改字节；本轮入口放在稳定老师题库和“我的反馈”。今后的老师试用 revision 在冻结前应包含返回题库或反馈入口。

## 结果与限制

- 六维表单从默认流程降为兼容的可选工具；自由反馈成为新试用任务的默认提交方式。
- “已反馈”只证明收到过针对精确 revision 的意见，不自动等于满意、接受、学生学会或跨题有效。
- 474 的转述反馈保留真实来源边界；若老师以后直接补充，新版本会标记为老师入口提交。
- 静态页面、feedback-only 服务和私有 OSS 对象需要分别发布或追加写入后才会在线生效。

## 不采用

- **继续只靠微信或口头转述：** 无法从老师长期入口恢复精确版本状态，也无法形成稳定产品闭环。
- **让 474 补填旧六维表单：** 会给已经完成的老师反馈制造额外义务，并改变证据原意。
- **把转述意见伪装成老师在线提交：** 混淆来源，破坏直接证据与产品记录边界。
- **原地修改 474 revision：** 破坏已经发布版本的不可变身份。
