# ADR 0008：静态成品验证阶段与单一发布边界

- 状态：已采纳
- 日期：2026-08-05

## 背景

项目预计至少进行三次老师交付，因此需要可复用的发布闭环；但当前首要产品问题仍是“生成出的互动课件是否对老师和学生有价值”，不是“老师能否自助调用模型生成”。此前把练习题误归类为不得公开的内部试卷，因而同时维护 GitHub Pages 老师入口与 OSS 私有课件直链。q01 v8 更新 OSS 后，老师实际使用的 Pages 仍指向旧工件，局部哈希验收却一度错误放行。为修复这次可恢复的试用事故，又逐渐引入与风险不相称的通用门禁和安全审查成本。

公开仓库本身不是模型凭证的安全边界。题目与课件可以公开；真正需要保护的是模型 API key、云控制凭证、评价写入和其他会产生费用或改变外部状态的能力。

## 决策

1. **先验证静态成品价值。** 当前外部老师只体验由内部人员或内部 Agent 预生成并验收的静态课件，并提交六维评价；老师自助生成另设后续产品检查点，当前不开放公网模型生成。
2. **GitHub Pages 是静态课件唯一生产渠道。** OSS 不再承担课件网页投递，也不作为“老师已收到正确 revision”的证据；OSS 只保留评价数据、生成产物等对象存储职责。
3. **稳定题库入口指向不可变 revision。** 老师长期题库 URL 保持稳定；每个精确课件 revision 使用新的 Pages 目录，发布后不覆盖。题库卡片只指向当前获准 revision，旧 revision 保留用于追溯或回退。
4. **真实入口是发布事实源。** 发布后的机器门禁必须从不含访问码的老师题库 URL 解析卡片并跟随到课件，再核对预期 revision、线上 SHA、必要资源与评价入口；旁路 URL、本地候选或 OSS 副本不能替代该证据。
5. **日常发布采用两级放行。** 机器门禁通过后，由产品负责人实际打开老师长期题库并确认当前卡片可用，再决定是否发送。老师实际发送前保持 `outcome: pending`。
6. **安全审查按能力变化触发。** 普通静态课件 revision 不再重复 Codex Security、OSS manifest 对账或独立安全审查。只有变更凭证处理、API 鉴权、云权限、远端删除、评价写入或发布脚本本身时，才进行一次与变更范围相称的独立安全复核。
7. **评价与模型凭证隔离。** 在线六维评价继续保留，但其运行服务不得包含 Kimi key，只允许访问码校验、评价 schema 校验和固定 OSS `feedback/` 前缀写入。现有公网生成服务在该隔离链路可用前后完成停用；重新开放生成能力必须另经产品与成本检查点。
8. **公开内容与受保护能力分离。** 题目和课件默认允许公开浏览；随机题库路径只用于体验分组，不冒充保密机制。访问码只保护评价、模型调用等外部写入或费用能力，不保护静态内容。

## 结果

- 至少三次老师交付复用同一条 Pages 发布与验收路径，消除 Pages/OSS 双生产工件漂移。
- “老师看到旧版本”按可恢复试用事故处理：用不可变 revision 和真实入口门禁预防，不用每轮高成本安全审查追求形式化证明。
- 当前 q01 v8 在评价隔离、Pages 不可变发布和真实入口验收完成前继续保持 `teacher-ready-suspended`、`outcome: pending`。
- 既有 OSS 私有投递实现保留但冻结；除非未来出现新的保密或交付需求，不再扩建或列为课件发布前置。

## 不采用

- 把 GitHub Free 仓库改为私有：会取消当前 Pages 发布，且不能解决浏览器可见 API 地址或服务端滥用问题。
- 同时把 Pages 与 OSS 都当作课件生产渠道：会重新引入版本漂移和验收对象错配。
- 当前直接开放老师自助生成：会在静态成品价值尚未验证时提前承担公网模型凭证、费用和鉴权复杂度。
- 每个静态 revision 重跑全量安全审查：与可恢复事故的风险等级不相称，且不能替代真实用户路径验收。
