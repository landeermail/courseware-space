# ADR 0008：静态成品验证阶段与单一发布边界

- 状态：已采纳
- 日期：2026-08-05
- 修订日期：2026-08-13
- 演进：静态发布与真实入口边界继续有效；老师反馈形式和研发实验默认路径见 ADR 0011

## 背景

项目预计至少进行三次老师交付，因此需要可复用的发布闭环；但当前首要产品问题仍是“生成出的互动课件是否对老师和学生有价值”，不是“老师能否自助调用模型生成”。此前把练习题误归类为不得公开的内部试卷，因而同时维护 GitHub Pages 老师入口与 OSS 私有课件直链。q01 v8 更新 OSS 后，老师实际使用的 Pages 仍指向旧工件，局部哈希验收却一度错误放行。为修复这次可恢复的试用事故，又逐渐引入与风险不相称的通用门禁和安全审查成本。

公开仓库本身不是模型凭证的安全边界。题目与课件可以公开；真正需要保护的是模型 API key、云控制凭证、评价写入和其他会产生费用或改变外部状态的能力。

## 决策

1. **先验证静态成品价值。** 当前外部老师只体验由内部人员或内部 Agent 预生成并验收的静态课件，并提交六维评价；老师自助生成另设后续产品检查点，当前不开放公网模型生成。
2. **GitHub Pages 是静态课件唯一生产渠道。** OSS 不再承担课件网页投递，也不作为“老师已收到正确 revision”的证据；OSS 只保留评价数据、生成产物等对象存储职责。
3. **稳定题库入口指向不可变 revision。** 老师长期题库 URL 保持稳定；每个精确课件 revision 使用新的 Pages 目录，发布后不覆盖。题库卡片只指向当前获准 revision，旧 revision 保留用于追溯或回退。
4. **真实入口是发布事实源。** 发布后的机器门禁必须从不含访问码的老师题库 URL 解析卡片并跟随到课件，再核对预期 revision、线上 SHA、必要资源与评价入口；旁路 URL、本地候选或 OSS 副本不能替代该证据。
5. **日常发布采用两级放行。** 机器门禁通过后，由产品负责人实际打开老师长期题库并确认当前卡片可用，再决定是否发送。老师实际发送前保持 `outcome: pending`。
6. **安全审查按能力变化触发。** 普通静态课件 revision 不再重复 Codex Security、OSS manifest 对账或独立安全审查。只有变更凭证处理、API 鉴权、云权限、远端删除、评价写入或发布脚本本身时，才进行一次与变更范围相称的独立安全复核。
7. **评价与模型凭证隔离。** 在线六维评价继续保留，但其运行服务不得包含 Kimi key，只允许访问码校验、评价 schema 校验和固定 OSS `feedback/` 前缀写入。现有公网生成服务在该隔离链路可用前后完成停用；重新开放生成能力必须另经产品与成本检查点。
8. **公开内容与受保护能力分离。** 题目和课件默认允许公开浏览；随机题库路径只用于体验分组，不冒充保密机制。访问码只保护评价、模型调用等外部写入或费用能力，不保护静态内容。
9. **当前保留单仓库，但仓库根目录不是发布目录。** GitHub Pages 工件只能由明确的静态站点白名单组装；`production/`、`services/`、`research/`、开发证据和内部文档不得因为位于同一仓库而自动进入 Pages 工件。切换后老师现有 URL 和不可变 revision 路径必须保持不变。
10. **仓库架构只走一条渐进治理线。** 发布边界、职责分区、材料生命周期和迁移顺序共同构成一份目标架构与迁移计划，不另建平行的“归档治理”或“证据治理”。先建立可验证的发布边界，再在实际修改相关区域时逐步归位；历史材料由其所属模块或 Git 历史承担，不创建与产品、服务、生产和研发平级的顶层杂物仓。当前不为了整齐立即拆仓，也不一次性重排全部路径；只有边界仍无法独立演进或权限要求出现真实冲突时，才重新裁决拆仓。
11. **Pages 产品面收缩为静态体验。** 线上只保留公开静态课件、老师长期题库及评价页面；根首页不再展示已经关闭公网能力的生成器。`research/generation/` 内的生成器、benchmark、模板示例、研发证据和内部试用工具继续保留供本地研发，但不进入 Pages 工件。
12. **目标架构按四个职责模块收敛。** `site` 负责唯一 Pages 静态源，`production` 负责受版本控制的单题当前状态与必要输入，`services/feedback` 负责评价后端及其打包部署接口，`research/generation` 负责本地生成器、Kimi 客户端、harness、模板和生成实验。`scripts/` 只提供仓库级小接口，`docs/` 只保存正式知识。模块名是渐进迁移目标，不授权一次性搬迁现有路径。
13. **发布与恢复各自只有一个小接口。** Pages 通过 `scripts/build_pages.py --output <dir>` 组装并验证白名单工件；单题恢复只读取受版本控制的精确 `production/courseware/<courseware_id>/record.md` 及其当前必要引用。生产记录不复制协议、截图集、完整日志或被替代推导；可再生证据默认不进 Git，必要历史由所属模块或 Git 历史承担。
14. **迁移分批且每批只有一个风险主题。** 第一批只建立 Pages 白名单、移除线上生成器入口并证明现有老师链接与全部保留 URL 不变；不同时迁移生产控制面。第二批再压缩并版本化 q01/q07 当前状态、切换生产 skill 定位路径。评价服务只在后端实际修改时收拢，生成研发只在重新开展该方向时收拢，静态源码物理迁入 `site/` 最后进行。
15. **工件身份只服务冻结与发布。** 哈希、manifest 和 revision 身份只在候选冻结、独立成品评审、不可变发布和线上精确身份核验中使用；可变预览、产品方向讨论、普通反馈和不改变发布字节的工作不围绕哈希运转。

## 结果

- 至少三次老师交付复用同一条 Pages 发布与验收路径，消除 Pages/OSS 双生产工件漂移。
- “老师看到旧版本”按可恢复试用事故处理：用不可变 revision 和真实入口门禁预防，不用每轮高成本安全审查追求形式化证明。
- 当前 q01 v8 在评价隔离、Pages 不可变发布和真实入口验收完成前继续保持 `teacher-ready-suspended`、`outcome: pending`。
- 既有 OSS 私有课件投递实现已退出当前树，由 Git 历史保留；除非未来出现新的保密或交付需求，不再扩建或列为课件发布前置。
- Pages 工件不再等同于完整 Git checkout，内部源码与证据不会随静态网站一起发布；单仓仍可共享代码历史和原子变更。
- 线上导航只承诺当前真实可用的静态体验，不再让“存在源码”冒充“已开放产品能力”。
- 新产品协调任务默认只读取 `AGENTS.md`、`CONTEXT.md`、当前议题真正相关的一份 ADR、精确生产记录和当前动作涉及的代码；不默认加载 `PROGRESS.md` 全文、历史任务书、旧截图、其他课件记录、全部 ADR 或聊天历史。

## 不采用

- 把 GitHub Free 仓库改为私有：会取消当前 Pages 发布，且不能解决浏览器可见 API 地址或服务端滥用问题。
- 同时把 Pages 与 OSS 都当作课件生产渠道：会重新引入版本漂移和验收对象错配。
- 当前直接开放老师自助生成：会在静态成品价值尚未验证时提前承担公网模型凭证、费用和鉴权复杂度。
- 每个静态 revision 重跑全量安全审查：与可恢复事故的风险等级不相称，且不能替代真实用户路径验收。
- 立即拆分多个仓库：当前产品边界仍在变化，迁移会先引入跨仓依赖、历史和发布协调成本。
- 一次性重排全部目录：改动面过大，难以与真实产品收益对应，也容易破坏现有稳定链接。
