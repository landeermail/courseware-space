# ADR 0007：产品全生命周期上下文与检查点裁决

- 状态：已采纳
- 日期：2026-08-04
- 最近修订：2026-08-13

## 背景

早期开发、产品化讨论、单题执行和成品评审长期混在少数超长对话中，形成两类风险：新对话缺少关键产品来路，旧对话又被大量命令输出、截图和局部修补占满。q01 `q01-v8-64f8df823ed7` 的首次 A1 还暴露出另一风险：评审者把内部状态编号错配到学习者可见卡片，直接给出 `changes-requested`；若产品负责人机械执行该结论，就会在正确工件上制造新回退。

项目需要同时保留长期学习能力、执行独立性和评审独立性，又不能让任一短期角色凭自己的记录改变产品方向。

## 决策

1. **产品协调是长期角色，不是永久对话。** 产品目标、领域术语和跨轮取舍写入正式知识源，单课件当前状态写入生产状态单；任何新的产品协调任务都可据此接续。单个对话只服务一个明确议题或里程碑，完成后归档，不保存为项目“大脑”，也不要求后续任务加载完整聊天历史。
2. **开发前模拟教学属于产品协调任务。** 它按题型族及课件教学方案的成熟度触发：新题型族完整进行，已有题型族的新边界、变式、复合结构或反例只做定向校准，已验证边界内的等价变式默认跳过。产品负责人以代理学习者身份参与，短期执行者不得主持或用自证代替。
3. **每个修订使用独立的短期前端执行上下文。** 产品协调任务先提供已批准的问题包、物理模型、课件假设和课件教学方案；执行者只实现前端课件候选、完成 A0 并回传证据，不承担后端、云资源、部署、发布、生产状态裁决或产品泛化决定。
4. **每个修订先做 A0，再按风险选择一次独立成品评审。** A0 是执行者自检，不能放行；未参与实现的评审者按精确 `revision_id` 在 A1 定向复查、A2 标准成品评审、A3 深度审计中三选一，先看成品、后查定向实现，只提交可复现的修订级证据与结论，不在同一次评审中修复。A 编号表示评审范围而非逐级关卡：新课件首次成品通常走 A2；只有生产契约变化、重复严重失败、系统性证据冲突或面向不特定公众的产品级发布等明确触发项才走 A3。产品检查点、发布门禁、老师评价与安全审查不使用 A 编号；GitHub Pages 的公开可读属性和向指定老师发送静态链接本身不触发 A3。
5. **所有上下文只通过生产状态单和正式知识源交接。** 产品事实以 `CONTEXT.md`、ADR、质量标准、代码与测试为准；单课件当前状态以其生产状态单为准。聊天历史、Codex 记忆和临时启动包只负责提供线索或导航，不成为新的事实源。
6. **任何执行或成品独立试用评审建议进入下一轮前都经过产品检查点裁决。** 至少核对：精确修订是否一致；直接证据是否支持严重级别；学习者可见语义与内部状态映射是否正确；结论是否符合现行课件教学方案与产品边界；建议动作是否会破坏已成立的认知顺序或能力。发生矛盾时保留原结论并标记为 `superseded`，不先修改工件；对同一修订纠偏复审或重新路由。
7. **每次分派执行任务、部署、发布、执行外部写入或改变生产状态前，强制重新读取 `BLOCKED.md`。** 产品协调任务必须逐项对照其中仍有效的触发条件，列出本次已触发、未触发及条件不明的事项，再决定是否允许下一动作；不得先凭对话记忆、历史结论或“上次未相关”判断它与本次无关。已触发事项必须进入当前生产状态单或执行交接，并在其要求满足前阻止相应动作。
8. **外部价值优先于内部完备。** 工作只分为直接交付、必要风险控制和可推迟优化；默认只做前两类。测试、门禁和文档用于支持交付，不能冒充产品进展；真实用户路径已经可用或当前只能等待外部证据时，停止继续扩建内部体系。同一假设连续失败而没有新证据时，先重构问题，不用增加流程层数掩盖停滞。
9. **老师意见是重要证据，不是自动产品命令。** 是否把单题经验泛化为题型族、课件教学方案或全局规则，由产品负责人和产品顾问结合正反例、适用边界与产品方向讨论裁决；没有固定反馈次数门槛，单次赞同或多次重复都不能替代解释与边界判断。
10. **等待外部反馈不等于全项目停工。** 被评价的精确修订保持冻结，证据流独立；同时最多推进一个与其教学内容正交的新题实验，不修改等待中的课件或基础设施，也不借并行任务提前泛化尚未沉淀的学习。
11. **Product Design 等插件按需进入，不持有项目记忆。** 它们可以提供设计探索、研究或成品审计证据，结论仍回到产品检查点裁决。
12. **产品协调任务按议题或里程碑更换。** 新任务开始时从正式知识源和相关生产状态单恢复，能够准确复述产品使命、角色边界、当前状态、下一动作以及哪些主张尚未获得老师证据后，即可归档旧任务；不再维护永久超长产品对话。
13. **`build-physics-courseware` 是单课件统一生产协议。** 每个课件固定沿九步主干推进：接题建档 → 确认物理 → 决定怎么教 → 确定实现蓝图 → 前端实现与 A0 → 成品独立试用评审 → 产品检查点 → 不可变发布与真实入口检查 → 老师评价与收口。物理复核和开发前模拟教学按已定义风险或成熟度条件触发；发布必须另获产品负责人外部写入授权。协议负责读取生产状态、判断下一执行角色并生成最小交接命令，未经明确授权不自动创建新任务。
14. **具体课件进入生产后，每次状态推进都必须使用统一协议。** 产品负责人确认某题进入生产即触发建档；此后物理复核、开发前模拟教学、蓝图、前端实现、A0、A1–A3、产品检查点、发布、真实入口核验、老师反馈和反馈迭代均通过同一协议与生产状态单衔接。尚未选定具体课件的产品方向讨论、协议自身建设、基础设施任务，以及没有新证据的等待不触发该协议。
15. **skill 采用三层触发保障。** 产品协调任务在“开始、继续、评审或记录某个具体课件反馈”等明确生产意图下允许隐式触发，并由 `AGENTS.md` 的必须使用规则兜底；所有新开的短期任务都在交接命令中显式调用 skill 并声明执行角色。隐式匹配不作为强制保证，启用前必须同时具备边界清楚的 description、正反例触发测试和完整协议实现；不因一般物理讨论、跨课件产品讨论或基础设施任务触发。
16. **生产位置和写权限由状态单显式声明。** 本项目使用 `production/courseware/<courseware_id>/record.md` 保存受版本控制的当前状态和必要引用，使用 `trial/private/questions/<question_id>/` 保存只读原题包、`trial/private/courseware/<courseware_id>/` 保存前端候选、`trial/private/development/<courseware_id>/` 保存临时过程证据，并在发布授权后由产品协调者把精确字节写入稳定老师题库下的不可变 revision 目录。前端执行者只写候选和任务证据；物理复核者与成品评审者不写工件；短期角色不得修改首页、题库入口、正式 revision 或生产状态。
17. **新课件使用可独立测试的最小静态架构。** 默认骨架为 `index.html`、`styles.css`、`model.js`、`app.js`、`test-model.mjs` 与本地 `assets/`；物理只在 `model.js` 形成单一真值，交互、渲染、公式和文字消费同一输出，不各自重算。新题型族不得读取既有课件实现来决定页面；不为单题引入框架、构建步骤、服务端或全站依赖。架构例外必须在实现蓝图阶段由产品协调者提出并获批，前端执行者无权临场改变。
18. **每个阶段使用同一完成契约。** 负责人、必需输入、阶段产出、通过/等待/阻塞证据和下一执行角色五项齐全后才可推进；缺项时协议停止，不凭记忆补全。短期执行者、物理复核者和成品评审者只回传结果包，不直接修改生产状态；结果包至少包含产物或评审目标身份、实际证据、未决问题和建议下一步，产品协调者核对后才更新状态单并生成下一交接。
19. **产品负责人使用自然语言，内部路由参数由协议生成。** 产品负责人只表达开始、继续、检查、反馈或派发等产品动作；产品协调者从正式状态解析生产记录、执行角色和进入模式。新短期任务的交接命令显式携带这些内部参数，但不要求产品负责人理解或手工维护它们。
20. **“继续”只在唯一活动记录时自动定位。** 产品负责人明确题号或课件身份时按正式生产记录精确定位；未点名而只说“继续”时，协议直接扫描生产状态单。若恰有一个 `workflow_state: active` 的记录则续接；若有多个则列出候选并请求选择；`waiting` 且没有新证据的记录不自动唤起。短期任务始终携带精确状态单路径，不另建会与状态单漂移的人工总索引。
21. **一次调用连续推进到真实边界。** 连续阶段若由同一产品协调者承担、输入充分且不需要新的产品裁决，可以在一次调用中完成，不按九阶段机械停顿。遇到角色切换、产品负责人批准、部署/发布/外部写入或生产状态变更授权、方向性歧义、证据不足或 `BLOCKED.md` 触发项时必须停止，明确报告当前状态与下一动作。
22. **短期任务使用固定最小任务包。** 产品负责人要求生成执行命令时，协议必须写明 skill、角色、精确状态单路径、唯一目标、当前阶段、正式知识源、读写边界、已批准的物理/教学/蓝图输入、检查级别、`BLOCKED.md` 触发项、停止条件和回传证据。任务引用正式记录，不复制聊天历史或给予开放式完善授权；缺少任何必需字段时不生成可执行命令。
23. **skill 使用带完成条件的渐进加载。** `SKILL.md` 保留全部分支共同执行的生产骨架及各步可检查的完成条件，同时承担触发、状态定位、角色/阶段路由和停止边界；九阶段专属细则、状态单模式、任务包模板和 A0–A3 规则置于主文件以明确加载条件直接指向的引用文件中。调用时只加载当前角色与阶段所需内容，同一规则不得在多处重复定义，并优先用正向目标表达预期行为。主体、引用和正反例触发验证全部通过后，才允许开启隐式调用。
24. **skill 验证分三层并设投入上限。** 依次执行结构检查、覆盖状态定位/路由/任务包与正反触发样例的确定性测试，以及经产品负责人另行授权后的两次低上下文真实试跑（一正一反）。不展开无上限多智能体审查；失败只定向修正并最多复跑两轮，仍失败即停止汇报。
25. **生产状态定位使用最小只读工具。** skill 提供确定性工具扫描和校验生产状态单、按题目或课件身份定位记录、识别唯一活动记录、检查阶段必填字段并报告下一角色或缺失项。工具无写权限，不生成工件、不做教学或产品裁决，也不触发部署、发布或外部写入；正式状态仍由产品协调者依据证据更新。
26. **项目记忆不是事实源。** Codex 内建记忆只保存稳定的个人偏好和少量正式知识导航；当前 revision、生产状态、证据、待办和授权必须重新读取仓库正式来源。本项目不再使用额外的 `project-memory` 工作流维护并检索第二套项目状态，也不因为记忆命中而跳过正式来源。
27. **每项工作具有默认预算和强制停止条件。** 开始时只确定用户可观察结果、最小修改范围、必要验证和停止边界；普通任务默认单任务、单执行者，不自行增加安全审查、架构评审、全库扫描、文档治理或通用框架。同一路径失败两次、约十五分钟没有新可验证结果、范围明显扩大、必须大量回读历史、需要新增基础设施或通用治理，或验证成本开始高于修改本身时，必须停止扩张，只报告卡点、已有证据和最经济的下一选择。不得通过增加 Agent、测试、文档、哈希或审查继续掩盖停滞。

## 结果

- 开发前校准、前端实现、成品独立试用评审和产品决策彼此分工，但不会形成多个长期事实源。
- 新对话可以凭正式知识和生产状态继续工作，不必加载全部历史聊天。
- 外部动作与生产状态变化不会只凭长期记忆放行；`BLOCKED.md` 的当前触发条件必须在每次动作边界重新检查并留痕。
- 成品独立试用评审仍可能犯错；产品检查点负责发现证据—结论矛盾，但不能以产品偏好否定可复现缺陷。
- 新题型开发不会因为“每题固定模拟”长期依赖产品负责人，也不会因为已有相近知识点而跳过真正未知的题型边界。
- 内部流程在真实用户结果之外有明确上限；等待反馈期间只允许一个正交实验，防止重新形成多线基础设施建设。
- `teacher-ready` 只表示精确修订可以交给老师，不等于已经交付、老师接受或题库晋升。
- 各对话的完整日志保留为可追溯历史，不进入默认上下文；只有形成稳定术语、长期决策或可复用规则时才更新正式知识源。
- 记忆可以减少对个人偏好和入口位置的重复说明，但不能承担项目恢复、状态路由或发布放行。
- 工作预算不是产品功能的时间盒；它限制的是无新证据的内部扩张。真实复杂任务可在产品负责人看到证据和新估算后明确扩大范围。

## 不采用

- 保留一个永久执行对话和一个永久评审对话：会继续累积局部历史并削弱修订级独立性。
- 让评审结论自动驱动修改：无法防住范围、编号或证据解释错误。
- 每道题固定重跑开发前模拟教学：会把校准活动变成永久人工依赖，无法随题型族成熟退出。
- 只按老师反馈次数决定泛化：会把证据解释退化为投票，忽略产品方向、反例和适用边界。
- 把旧对话压缩成一份新的长期“大全”或继续维持永久产品对话：都会制造与正式文档并行、必然漂移的第二套知识库。
