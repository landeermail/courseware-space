# ADR 0005：产品边界定位——想象层产品，以解题层交接质量验收

- 状态：已采纳
- 日期：2026-07-31

## 背景

老师首评 q01（feedback-7d414bc2，2026-07-30）整体打回：过程可见、与解题的衔接两维不过，并留下「信息不是越多越好，有逻辑的信息才是有效信息」的总纲。讨论产品定位时出现过两个极端表述：课件应对学习效果负责到底（A），或「打通想象就够了，更深处是老师的主场」（B）。两个方向都必须证伪后才能定边界。

## 备选方案与证伪

- A（课件负责到底）：动机是补齐学习闭环，但结局是制造老师刚打回过的信息过载，并与老师抢主场——完整讲解、逐步推演、训练系统都会被她视为噪音。
- B（打通想象即交差）：与老师的验收行为直接矛盾——她两次打回（q20/q21 校准、q01 首评）都落在第六维「与解题的衔接」。按 B 的边界，回应她 fail 的能量账本→列式与分析骨架恰好属于「越界」，砍掉后交付的就是已被她打回过一遍的东西。

## 决策

课件是想象层的产品，但想象层的验收标准是「能无缝交到解题层」：桥归我们造，桥的对岸是列式；讲课、训练与个体纠偏归老师。六维标准的第六维即交接质量检查，本 ADR 是把标准里已有的东西说破，不是新增方向。此后一切课件功能提案过四条边界测试：

1. 使命测试：是否让不可见过程变得可观察、可操控、可验证？
2. 结构/讲解测试：提供的是结构（账本、骨架、关系式）还是讲解（旁白、推演、答案复述）？结构进课件，讲解归老师。
3. 删除测试：删掉它，老师还能否从课件直接列式？能→装饰，删；不能→桥梁，留。
4. 演示测试：老师课堂演示时会不会想关掉它？会→是干扰不是辅助。

## 结果

- `CONTEXT.md`「想象鸿沟」按本定位修订；「有效信息」「老师审计视图」两个术语同轮确立，均落在本边界内。
- 反馈→标准的沉淀路径同轮确立：老师反馈由 `services/feedback/` 留存 → 提炼术语进 `CONTEXT.md` → 修订 `docs/quality/standard.md` 并标注 feedback 来源 → 课件按标准迭代 → 二次评审验证。「有效信息」作为六维元约束存在，不立第七维——防止标准膨胀导致 harness 判据失稳。
- 风险：四条测试的判定仍含主观成分，边界争议以老师的二次评审为最终裁决，不在内部反复推演。
