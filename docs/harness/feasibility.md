# 课件生成 harness 可行性验证

> 状态：2026-07-29 最终结论；K3-256K 抛体 5 题、圆周 5 题完成条件已通过自动审计。

## 结论

| 领域 | 结论 | 证据 |
| --- | --- | --- |
| 抛体运动 | **可行（限当前注册物理范围）** | 5 个 K3 生成物分别通过 5～6 组变形参数物理探针、桌面与 iPad 横屏浏览器交互；速度方向、能量、射程临界 3 类错均被拦截 |
| 圆周运动 | **可行（限 uniform/orbit/vertical_string）** | 5 个 K3 生成物分别通过 6 组探针和两视口交互；向心方向、能量、竖直最高点临界 3 类错均被拦截 |

核心假设成立：模型可以自由生成纯物理代码和教学视图，而物理正确性由模型外的确认闸、沙箱、独立参考计算和具名断言判定。它已经不是只能服务一个模板的演示。

但“无人审核、任意题型、直接发布”的产品假设尚未成立。真实验证仍出现首屏题设被覆盖、嵌套脚本、自动播放、无法暂停等视图错误；教学因果是否讲清也不能由物理断言证明。因此整体产品成熟度应记为 **部分可行**：物理护栏可用，自动发布仍必须经过浏览器检查和老师验收。

## 真实失败如何迭代 harness

1. 第一批 K3 抛体视图中 4/5 存在单引号字符串真实换行，浏览器报语法错误。harness 增加 Node 内联脚本语法检查，失败页不再被误计成功。
2. 留出集第一道平抛用滑杆中点覆盖老师确认的 `v₀/h/g`。渲染器现在包裹首次 `sample()`，场景字段和值不完全一致就亮红并终止。
3. 一道视图把三个 harness 占位符写进 `<script>`，渲染后形成嵌套脚本。契约现在要求占位符位于所有脚本之外。
4. 一道视图首屏立即 `play()`。提示与浏览器验收现在强制首屏停在物理时间 0，播放只由用户触发。
5. 一道修复视图读取契约外的 `timeline.playing`，导致无法暂停；累计 3 次后保留为失败，另用不同题补足 5 个成功样本，没有手改生成代码。
6. 圆周转盘三次都因 JSON 解码后的字符串换行被拒。harness 现只对单/双引号字符串内的真实换行做确定性 `\n` 规范化，模板字符串、注释和物理代码不动；规范化结果仍需通过 Node 语法检查并写入元数据。

这些案例证明重试只有在失败能反向形成守卫、断言或确定性规范化时才有产品价值。单纯重复同一提示不会形成成熟 harness。

## 机器可判范围

### 抛体

- 精确输入/输出 schema、有限数值、量纲关系和采样轴一致性；
- 水平/竖直位置、速度分解与重力加速度方向；
- 动能、势能、机械能自洽与守恒；
- 落地时间、射程、顶点时间/高度和等高 45° 射程极值；
- 改变速度、重力、角度、高度、采样数量后仍需成立，防止硬编码题设答案。

### 圆周

- 圆周几何、速度切向、加速度径向向内和 `ΣF_r=mv²/r`；
- 匀速圆周的周期和能量；
- 天体引力、轨道速度、周期与中心天体质量/半径的闭合；
- 竖直圆周的能量、绳张力、变速周期数值积分；
- 最高/最低点临界速度、最高点张力非负和亚临界场景拒绝。

## 仍需人工或后续工程兜底的缺口

1. **教学是否真正讲清。** 浏览器只能证明可见、可操作和数据联动，不能证明学生建立了正确心智模型；最终仍需老师验收。
2. **断言只覆盖注册语义。** 阻力、碰撞、非匀强场、刚体或新受力模型必须先增加独立推导与正反例，不能套用“通用 harness”直接放行。
3. **自由视图仍可能运行错误。** `timeline.playing` 的真实失败说明静态契约不是完整 JavaScript 语义证明；正式入口必须保留浏览器运行验收。
4. **读数的教学信息密度不稳定。** 月球轨道题改半径后确实重新采样，但 `t=0` 状态句没有显式写出新半径，属于教学表现缺口而非物理错误。
5. **确定性规范化范围刻意很窄。** 只修复引号字符串真实换行；括号、变量、控制器 API 等其他错误继续拒绝，避免 harness 猜测并改写模型意图。
6. **本地 Node `vm` 不是生产多租户沙箱。** 正式执行自由代码前需要无凭证、只读文件系统、断网、CPU/内存/时间受限的进程或容器边界。
7. **当前 Kimi Code 仅用于私人研发。** 面向公众或收费前必须迁移 Kimi Platform，或取得产品后端用途的书面许可。

## 质量与用量观察

当前基线固定 `k3-256k`、`reasoning_effort=high`、JSON Mode、分阶段缓存键和代码级输出上限，不允许 K2.7 fallback、1M、HighSpeed 或环境变量切换。

构成最终验收清单的执行链（包含诚实失败与修复）共 36 个 provider 请求、244,016 total token，其中 reasoning token 136,543、cached token 12,858：

- 抛体相关 20 请求、125,683 total token；包含 1 次空响应、4 次契约/物理拒绝和一个浏览器重试上限失败样本；
- 圆周相关 16 请求、118,333 total token；原始尝试中 7 次被物理或视图契约拒绝，转盘视图最终由确定性换行规范化复用，无新增模型调用。

样本量仍不足以制定生产单题价格。按 ADR 0004，先累计至少 30 道真实题再根据合格产物总成本收紧输出上限；当前不可用单次调用价格推断盈利能力。

## 扩题型建议

不建议立即“大规模复制题型”。建议进入受控扩展：每次增加 1～2 个机制差异明显的领域，先写独立断言和正反例，再跑冷样本、浏览器验收和老师验收；失败必须反向形成可复用护栏。保持 `staging → 机器物理验收 → 浏览器验收 → 老师确认 → library`，在 30 道跨领域数据证明合格率和成本稳定前不开放自动发布。
